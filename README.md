# 点亮地球

一张用来收藏旅行经历的私人地图。旋转地球、放大到已接入的地方行政区，点亮到访过的区域，再把日期、照片和回忆留在地图上。

## 已实现的功能

- **探索地球**：真实行政边界、自由拖动与缩放、地球／平面切换、地名搜索、区域定位与点亮。
- **全球行政区覆盖**：接入 230 个国家与地区的地方边界，按当前视野加载；“全球覆盖”可查询各地实际层级、来源年份与缺失情况。
- **我的足迹**：同一地区可记录多次到访，填写标题、旅程名称、文字和照片；记录支持编辑、删除与撤销。
- **四种状态**：去过、住过、途经、想去。去过和住过计入已到访统计；途经和心愿分别保留。
- **时间轴**：按年份筛选地图与记录，也可填写“2024 年春天”等近似时间，或暂不填写日期。
- **心愿地图与旅行护照**：收藏想去的地方；依据实际记录解锁初次点亮、地方足迹、跨国旅行、重访、照片和居住印章。
- **照片备份**：导出全部记录或当前年份的 ZIP，包含 `atlas.json` 和照片文件；导入时校验记录与照片，跳过已有记录 ID，保留原有内容。
- **响应式界面**：桌面侧栏与窄屏抽屉布局，支持键盘搜索与减少动态效果偏好。

网站首次使用为空白地图，不会将演示旅行混入个人记录。

## 地图覆盖与限制

世界概览包含242个国家、属地等地理实体，不能解释为主权国家数量。当前地方层覆盖 **230个国家与地区、144,486个区域对象，143,776个活动区域（含不同来源年份）**。2026-10-26为原37个缺口补入22个地区，升级6个已有地方层，并核实13个原ADM1地区本已是基层市镇、教区或村，纠正原先的省州提示。

目前4项仍仅提供较粗细分：巴林、利比亚、圣赫勒拿及法属南部和南极领地；15个地区仍未接入独立地方边界。各项原因、来源和部分覆盖标记可在“全球覆盖”查看。ADM层级号不能直接对应中国县级，不能声称全球县级区划已齐全。完整目录、58项调查及许可见 `public/data/coverage.json`、`coverage-gaps.json` 和 `sources-supplements.json`。

使用时先搜索国家或在“全球覆盖”中选择“查看地方地图”，载入后可搜索该国地方名称，也可直接放大并点击边界。地图在可交互后主动预加载初始视野、足迹涉及及随后浏览的国家，最多6份资产并发，后台最多占2份。桌面解码缓存192MiB、索引32MiB，国家图层最多12个并另受160MiB源JSON预算约束；手机使用96MiB解码缓存及6个图层。冷启动跳到具体县市时先显示该处精确视口，后台补齐后安装完整国家几何，之后平移和缩放由MapLibre直接复用。校验过的不可变公共几何也保存在浏览器CacheStorage，刷新后可复用；缓存不可用时自动使用网络。首访仍需下载，数据缓存不包含旅行记录或照片，也不提供整站离线保证。

点亮按真实多边形整块着色，四种状态使用不同颜色。新保存或改变状态时有约1.1秒的柔和亮起效果，减少动态效果偏好下直接显示。全景保留小区域定位标记，放大后以色块为主。已保存色块独立于六国探索缓存，筛选、删除和撤销同步更新；旧图层文件与ID保留，换源前的回忆也能按原区域着色。

中国大陆区县已是现行边界（见下段）；其他国家和地区的边界仍是各来源年份的历史快照，不代表当地现行区划。

中国大陆31个省级行政区的县级区划都已换成现行边界：26个省区市取自OpenStreetMap 2026-11-21快照（`scripts/prepare-china-current.py`，共2450个县级单位），苏沪浙皖赣沿用此前的2026-10-25快照与官方名录，合计2863个现行区县，名称与区划代码经Wikidata核对。2017年旧区县全部保留为历史版本，旧足迹照旧着色；2017年来源画在现行省界以外的较大残片（藏南、札达等争议地区及西部边境8处）保留为接边副本。旧GB来源不自动视为现行，行政类型冲突和未经核实名字隐藏误导标签；部分来源原文仍可搜索。杭州按 2021 年批复改为上城、拱墅、余杭、萧山、临平、钱塘的现界，江干区和下城区只保留给旧回忆。中国以外的140,389个地方区域中，88,820个已有Wikidata中文名，129,760个配上了中文上级（省、州、府等）；没有中文名的保留原文名，并显示中文上级，如“Totontepec Villa de Morelos · 瓦哈卡州 · 墨西哥”，不做自动音译。同名区域使用独立、稳定的地区 ID。

完整来源、原始许可、年份差异、地名核验和转换步骤见 [地图数据说明](docs/data-sources.md)。发布时需保留 Natural Earth、geoBoundaries、OpenStreetMap contributors 和 US Census Bureau 等署名及对应许可。

## 私密保存与备份

正式站点使用 ChatGPT 登录身份；入口可供持有链接的人登录，每个账号的旅行记录和照片仍按本人身份私密保存。旅行记录存入 Cloudflare D1，照片存入 R2；所有记录和照片接口都在服务器端按账号检查归属。未保存的编辑草稿保存在当前浏览器会话中，不能替代已保存记录或 ZIP 备份。

每段回忆最多 6 张照片。上传支持 JPG、PNG 和 WebP，原图需小于 25 MB；浏览器将照片转为最长边不超过 1,800 像素的 JPEG 副本，服务器对每张文件限制为 4 MiB。ZIP 备份包含这些浏览副本，原始照片请继续保留在自己的相册中。

备份导入上限为 200 MB。照片较多时可按年份分别导出。导入采用追加方式，已有 ID 不被覆盖；中断后可以再次导入，已恢复的记录会跳过。导入会恢复旅行记录的创建与更新时间。备份文件本身包含私人文字和照片，应保存在自己控制的位置。

## 离线桌面版

同一套界面可以打包成不需要账号、不依赖网络的桌面应用。应用内置全部地图数据（约 250 MB），旅行记录和照片保存在本机的一个文件夹里：

- macOS：`~/Library/Application Support/点亮地球/atlas/`。其中 `atlas.json` 是记录，`photos/` 是照片文件，`atlas.backup.json` 是上一次保存前的副本。
- 应用内“备份与设置 → 打开数据文件夹”可以直接打开这个位置。
- 从网站迁移：在网站“备份与设置”里导出全部备份，再在桌面版里导入同一个 ZIP。两边的备份格式相同。

桌面版与网站共用 `components/` 和 `lib/`。差别只有三处：`lib/local-api.ts` 用本机存储实现与 `app/api` 相同的接口和校验；`desktop/main.ts` 是 Electron 外壳，通过 `atlas://app` 提供界面、地图数据和上述接口；`lib/runtime.ts` 让界面在桌面版里去掉登录相关的部分。

构建并安装（在 macOS 上一条命令完成）：

```sh
npm run desktop:install            # 检查、测试、构建、打包、装进“应用程序”并打开
npm run desktop:build              # 只构建，不安装
```

`desktop/release.mjs` 在 `~/Library/Caches/light-the-earth/` 里工作：复制一份项目（构建和测试会写入源码目录）、离线安装打包工具（Electron 只装在这里，不进入网站的依赖），输出也放在这里。这个位置不随项目云同步，也不会被系统定期清理，缺什么下次会自动补上。打包工具不在本机缓存里时，加 `--allow-download` 允许联网下载。应用正在运行时脚本会停下；加 `--quit` 则先请它正常退出再替换，正在编辑但未保存的回忆会丢失。旅行记录不在应用里，替换应用不会动到它们。可选参数见脚本开头。

也可以分步手动构建：

```sh
npm run build                      # 先生成打包后的地图数据 dist/client/data
npm install --prefix desktop       # 首次需要
ATLAS_DESKTOP_OUT=/其他目录 node desktop/build.mjs   # 输出 <目录>/release/点亮地球-<平台>-<架构>/
```

`--platform=win32 --arch=x64` 可以生成 Windows 版，尚未在 Windows 上实测。应用未做苹果公证，拷到别的 Mac 上首次打开需要右键选择“打开”。

## 本地开发

需要 Node.js `>=22.13.0`。项目采用 React、TypeScript、Vinext／Vite、MapLibre GL、Drizzle 与 Cloudflare Workers，部署资源声明位于 `.openai/hosting.json`，绑定名为 `DB` 和 `BUCKET`。

首次安装与构建：

```sh
npm run install:ci
npm run build
```

首次使用本地数据库时，在项目根目录执行当前迁移：

```sh
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_magical_shatterstar.sql
```

该迁移只针对本地预览数据库，已经执行过的数据库不要重复应用。后续修改 `db/schema.ts` 后，用 `npm run db:generate` 生成新迁移，按顺序应用尚未执行的文件；如资源绑定变动，先重新构建以更新 `dist/server/wrangler.json`。正式部署由 Sites 流程单独应用生产迁移。

启动开发预览：

```sh
npm run dev -- --port 5178
```

浏览器打开 `http://127.0.0.1:5178/`。Portable 本地环境可通过 `/signin-with-chatgpt?return_to=/` 使用模拟账号 `local_seedy` 登录；该模拟身份仅用于回环地址开发，不包含在生产构建中。本地 D1、R2 与登录状态独立于正式站点，预览数据不会自动同步上线。

验证与构建：

```sh
npm test
npm run typecheck
npm run build
```

测试覆盖账号隔离、记录与照片校验、照片引用的一致性、备份边界、时间戳和统计逻辑，以及全球边界清单、稳定 ID、加载并发、取消和缓存淘汰。地图 WebGL 渲染、文件选择、照片上传、ZIP 下载恢复及窄屏布局还需要在真实浏览器中验收。`npm start` 可预览构建后的 Worker，使用终端输出的本地地址；它不会发布站点。

## 维护约定

- `components/AtlasApp.tsx` 负责页面与收藏流程，`EarthMap.tsx` 负责地图交互，`MemoryEditor.tsx` 负责记录编辑。
- `app/api/` 负责需要账号身份的读写；校验规则在 `lib/validation.ts`，表结构在 `db/schema.ts`。
- `lib/backup.ts` 与 `lib/archive.ts` 负责 ZIP 备份及有限量解压；备份格式修改需保留版本识别与兼容策略。
- `public/data/` 保存可随站点分发的边界、来源和校验结果。`scripts/prepare-geodata.py` 重建世界层与原有三国，并保留其他国家的覆盖条目；`scripts/prepare-global-geodata.py` 从保存的来源目录重建全球地方层。依赖、复现命令和两组离线校验见 [地图数据说明](docs/data-sources.md)。需保留稳定区域 ID、来源年份与许可。
- MapLibre Worker 作为本地文件放在 `public/vendor/maplibre-gl-6.15.0/`。升级 MapLibre 时同步更新 Worker、许可证及地图中的 Worker 路径，并重新检查浏览器渲染。
- 使用 Sites 技能的构建、源码归档和私密发布流程更新已绑定站点；不要为同一项目重新创建站点。保留 `.openai/hosting.json`、迁移与源代码，勿提交凭据、`.wrangler/`、`.sites-runtime/`、`.vinext/`、`node_modules/` 或构建产物。

原始运行环境、登录适配及 Sites starter 的详细说明保留在 [维护参考](docs/starter-reference.md)。

## 白天模式与细地图对齐

外观默认跟随系统，并实时响应系统主题切换；“备份与设置 → 外观”可选择跟随系统、白天或夜晚。手动选择保存在当前设备，切换时保留地图视角和旅行记录。

放大后，230个已接入地区的陆地轮廓从相同的地方行政面合并得到；详细区划载入后隐藏原有概览底图，避免两套来源轮廓重影。中国、日本、美国改用更少简化的固定来源；香港18区采用官方边界结合OSM实际海岸线，保留旧ID并隐藏港澳14个重复显示单元。地图可放大至16级。其他地区仍受原始来源年份和精度限制，地图不作为测绘或现行区划认定依据。

## 其他国家的精度扩展与宇宙背景

本轮提高24国38,408个原有地方单元的几何精度，原ID保留，顶点总量约为旧显示文件的3.43倍；逐国约2.09—4.35倍。法国另接入35,010个源载市镇及市辖区单元，本土与科西嘉显示34,881个，129个海外单元由已有属地图层单独显示。巴黎、里昂、马赛使用来源中的市辖区划分，边界年份和来源限制在目录中保留。

现行点亮色块、地方填充和边界使用同一份主几何。法国320个旧区域回忆使用原始2022年ADM3区界；此前的市镇合并推导仅作为审计档案保留，不再用于运行时着色。历史区界可能与其他年份的现行市镇层交叉，界面按历史身份说明。压缩源文件与内容哈希分片均无损保留几何；浏览器以完整国家预加载和保存ID读取分片，应用单次读取预算96MiB、256片，每片仍最多2MiB解码数据；每片保持完整SHA校验。Git保留可还原的压缩源，测试与构建前自动还原原文件。

地球视图使用独立深蓝宇宙背景、蓝色海洋和大气边缘；背景中的少量星点由透明地图画布自然露出，随球体投影正确遮挡。平面地图保持海洋底色。白天/夜晚及系统跟随继续可用。

## 地名质量检查与第二批精度提升

本轮再提升35个国家、44,044个既有地方单元的精度，顶点总量约增至旧显示文件的3.24倍；原ID、层级与边界年份保留。单国最高解压文件约11MB，传输文件小于4MB。详情和复现脚本见`precision-remaining.json`。

东京湾原“?????”面经日本国土交通省2017及2025年行政区数据核验，显示为“千葉県所属未定地”，并明确它尚未归属普通市区町村；山梨另一处损坏名称为“富士吉田市”。日本共26项、匈牙利15项经官方名称及空间证据核验。另恢复582项可逆编码损坏地名，包括法语重音和毛利语字符。

`prepare-name-quality.py`审计全部当前源要素名称与标注点。56个尚无可核验地名的源区域保留边界与记录能力，在详情中标明待核实，地图不显示错误名称；10个原标注点移至自身最大多边形内部。所有修复均为显示层覆盖，不改原始边界和私人已存地区信息；备份、旧记录编辑及删除撤销保留原地区元数据，新记录使用当前已核实显示名称。


本批行政区版本与接边处理见 2026-10-27复核记录。英国361个地方行政区、挪威357个市镇及浙江90县使用本批数据。其他地区继续按来源年份标示。

放大到地方边界出现的级别（3.45）起，所有国家都显示县市级区划线。中国、印度、法国等大国的精确边界要到 5.5 或 6.5 级才进入视野渲染，尚未挂载的国家也暂时没有精确图层；这些情况下显示一份只用于画线的概览网格（`public/data/overview-borders.json` 及 `public/data/overview/`），精确边界出现后自动让位。网格在构建时切成第 3–6 级矢量瓦片（`public/data/overview/tiles-<哈希>/`），地图只读取视野内的瓦片；早先整份以 GeoJSON 交给地图引擎时，引擎线程常驻约 1 GB 内存，桌面版启动即占用 3.4 GB，改为瓦片后降到约 1.4 GB。瓦片坐标比网格更细，切片不损失精度。回到地球全景（缩放低于区县线出现的级别）静置 30 秒后，不在视野内的国家精确边界和分片读取器的内存缓存会被释放；桌面版随后做一次压缩式垃圾回收（主进程以 `--expose-gc` 启动），逛过多国后约可再还给系统 350 MB。之后再放大会从本机磁盘缓存重新读取，北京一带约 0.4 秒恢复区县显示。点击、点亮和保存始终使用精确多边形。窄屏不加载这份网格。同一份清单里还有一层“国界接缝补色”：相邻国家的精确边界来自不同来源，常常对不上，陆地国界上会露出海色的细缝；这层补色垫在精确陆地下面，沿每条陆地国界把缝补成陆地色。两国来源越不一致，补的缝越宽（约 4 到 12 公里）。只有横跨国界的缝才会被量入和补上：既靠近国界线、又同时靠近两国陆地的水面。只挨着一侧的港湾、海湾和湖，再窄也保持为水面（例如香港的维多利亚港、蓝巴勒海峡、吐露港，以及斯库台湖、维斯瓦潟湖）；界河按陆地显示。几何源更新后需运行 `outputs/geodata-venv/bin/python scripts/build-overview-borders.py` 重新生成。

离线更新资产后依次运行 `python3 scripts/apply-current-boundaries.py`、`outputs/geodata-venv/bin/python scripts/prepare-display-meshes.py`、`node scripts/build-region-index.mjs`，然后执行测试和类型检查。几何源更新时必须重建同源显示清单；正常前端构建无需Python，会从已审计gzip恢复数据并验证索引源哈希。地名审计重新生成后，再运行apply步骤补回历史版本说明。

台湾 368 个乡镇市区的中文名（繁体，当地写法）来自 Wikidata：`scripts/audit-taiwan-names.py` 读取缓存在 `outputs/taiwan-name-sources/` 的一次查询结果（查询语句同目录 `query.rq`），按每个乡镇的坐标落在哪块 2017 年边界里来匹配，再用来源自带的拼音名或中文名核对，对不上的单独列出、不猜。结果写入 `public/data/taiwan-name-repairs.json`，并合并进 `name-quality.json`；简体写法和拼音名作为搜索别名，所属县市一并补上，边界、地区标识和年份不变。`prepare-name-quality.py` 会读取这份修正，完整重跑地名审计也不会丢失。

中国 2017 年来源里仍是英文名或“旧来源待核实区域”的县级区域（153 个），由 `scripts/audit-china-county-names.py` 按 Wikidata 补上中文名：读取缓存在 `outputs/china-county-sources/` 的查询结果（县级、地级区划代码及前身关系，查询语句同目录），按坐标落在哪块区域里匹配，已被其他区域认领或重复的条目一律不用。2017 年后只改了建制的显示现行名称（如沙湾县→沙湾市）；之后被合并的显示当时名称（如带岭区、长治城区），这类和嘉峪关三区记在脚本的人工核对表里。来源英文名保留为搜索别名并写进说明。结果写入 `public/data/china-county-name-repairs.json` 并合并进 `name-quality.json`；任何重写 `name-quality.json` 的步骤之后都要重跑它。邯郸一块标为 Fuxing District 的区域和大连金州经济技术开发区暂无可核验的中文名；全国区县换成现行边界后，这两块和其余2017年区域一样只作为历史版本保留。

### GPT 账号隔离复核（2026-11-11）

私密接口根据服务器确认的GPT身份检查归属，客户端提交的owner字段不会决定归属。当前页面携带账号标记，服务器在页面账号与登录账号不一致时拒绝旧请求。会话失效、跨标签页换号及浏览器后退恢复时先隐藏私人内容，再核对当前身份；检查失败保持隐藏并可重试，不卸载地图或重下载边界。上传、导入和备份也绑定发起时的账号，备份下载前再次核对身份。共享地图缓存只保存公开几何数据。

本轮线上已验证真实当前GPT会话保存、刷新读回及测试记录清理，原10条记录所有字段保持一致；匿名请求及伪造GPT身份头均被拒绝。本地双身份SQLite测试覆盖跨账号读写、照片及ID冲突；真实第二个GPT账号的登录端到端仍需朋友配合，不能用本地模拟替代。

## 发布公开版

公开仓库 <https://github.com/Sugarrr1546/light-the-earth> 是这个仓库的独立副本：历史和作者信息与这里分开，每次同步在公开仓库里新增一次提交，作者用 GitHub 的 noreply 身份。

```sh
npm run publish:public              # 演练：导出、检查并列出将要公开的改动，不提交
npm run publish:public -- --push    # 提交并推送到公开仓库
```

`scripts/publish-public.mjs` 导出某个提交（默认 `main`，工作区须干净）里受版本管理的文件，去掉开发过程记录（`docs/reviews`、`docs/superpowers`），把指向它们的链接改成纯文字。之后逐个检查文件名、文件内容和提交说明；发现任何不应公开的文字就停下，什么都不发布。设置项放在本仓库的 git 配置里，不会被导出：`publish.remote`（公开仓库地址）、`publish.mirror`（公开仓库的本地副本，默认 `~/Library/Caches/light-the-earth/public-repo`）、`publish.name` 和 `publish.email`（公开提交身份），以及可重复设置的 `publish.forbid`（不得公开的文字，用 `git config --add publish.forbid ...` 添加）。本仓库的 `user.name`、`user.email` 和全局 `user.email` 自动列入，任何 `/Users/` 路径也会被拦下。
